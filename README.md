# 审计取证授权与程序留痕

控制审计计划、电子取证、协助查询和程序期限。

## 领域范围

系统涉及审计组人员、被审计单位、审计机关复核人员、审计机关负责人、协助机关人员、普通项目人员。当前领域资料记录以下业务事实：

- 审计监督覆盖财政收支、国有资源和重大公共工程，纳入统一案件脉络
- 年度计划、审计通知、事项范围和审计组成员只按批准版本生效
- 临时扩大范围须说明法定依据，并由未参与提出的人复核
- 电子资料分批交付保存摘要、来源、承诺与到达时间，相同交付号重试沿用原事实，异文转入证据争议
- 账户查询核验签发权限、两名执行人员和通知书期限，交金融机构的信息最小化，回执不能反向改写申请
- 打探干预、拒绝配合和跨机关协助进入不同的受限记录与期限队列，更正只新增版本
- 取证、封存和范围变更基于同一案件水位原子提交，失败不留中间状态
- 授权查询解释证据取得、使用记录与程序有效性，停机恢复后期限工作继续执行

`contracts/domain.schema.json` 定义领域资料结构，`fixtures/domain.json` 提供不含真实身份信息的示例，`src/audit_evidence_procedure/context.py` 负责读取并检查这些资料。

## 服务结构

全部案件事实以事件落账（`events.py`），状态由事件重放得出（`state.py`），
事件日志可快照、可恢复（`store.py`）。`service.py` 的 `AuditService`
承载全部命令与查询，`access.py` 定义角色与权限。

| 模块 | 职责 |
| --- | --- |
| `access.py` | 角色与权限；普通项目权限看不到金融账户查询材料与干预登记 |
| `models.py` | 案件、版本化文书、交付、争议、封存、账户查询、受限记录、期限事项 |
| `events.py` / `store.py` / `state.py` | 事件定义、追加式日志与快照、状态投影 |
| `service.py` | 计划版本、范围扩大复核、交付幂等、账户查询、受限记录、案件事务、期限队列、授权解释 |
| `clock.py` | 时钟抽象；手动时钟用于模拟停机与恢复 |

## 需求映射

- **统一案件脉络**：`open_case` 覆盖三大监督领域，`case_file` 汇总文书、交付、查询、受限记录与期限；受限栏目按权限省略。
- **只按批准版本生效**：四类文书经 `propose_document` / `approve_document` 流转，`effective_document` 只返回最新已批准版本。
- **临时扩大范围**：`request_scope_expansion` 强制法定依据并登记复核期限；`review_scope_expansion` 拒绝提出人及参与人复核，通过后在同一事务中生成新的生效范围版本。
- **交付幂等与争议**：`register_delivery` 按交付号幂等，重试沿用原事实不产生新事件；异文转入证据争议且原事实不被覆盖。
- **账户查询授权**：`request_account_query` 核验签发权限、两名不同执行人员（须在批准的审计组成员中）与通知书期限；`institution_payload()` 输出符合 `contracts/institution_payload.schema.json` 的最小化信息；`record_receipt` 只登记独立回执事实。
- **受限记录与队列**：三类记录分别进入意见期限、协助催办、复核工作队列；`correct_record` 只新增版本，原记录保留。
- **案件水位原子提交**：`commit` 把取证、封存、范围变更放入同一事务，共享同一水位；任一操作失败整体回滚。
- **授权解释与恢复**：`explain_evidence` 给出取得经过、使用留痕与程序有效性；`AuditService.recover` 从快照重放后，期限队列、协助催办与复核工作继续执行。

## 开发命令

- 运行测试：`python3 -m unittest discover -s tests -v`
- 编译检查：`python3 -m compileall -q src`

上述命令只读取仓库内资料，不需要连接外部业务服务。
